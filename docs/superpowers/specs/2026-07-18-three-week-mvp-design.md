# 三周 MVP 收缩设计

## 1. 目标

在三周内，由 AI 主要完成编码、项目所有者负责评审与调试，交付一个可运行、可评测、适合求职演示的电商售后 AI 客服纵向切片。

项目不以 Agent 数量或技术组件数量为目标，而以一条完整业务链路的可靠性为目标：

```text
用户提出退货
→ 查询订单事实
→ 检索当前生效政策
→ 确定性规则判断资格
→ 高风险进入人工审批
→ 从持久化检查点恢复
→ 幂等创建模拟售后申请
→ 返回带证据的结果
```

## 2. MVP 范围

### 2.1 必须交付

- 多轮会话与状态持久化。
- 政策知识问答及来源引用。
- 订单查询与用户资源归属校验。
- 退货字段收集与确定性资格判断。
- 高金额、政策冲突、低置信度等风险升级。
- 人工审批、中断、服务重启和流程恢复。
- 模拟售后申请的幂等创建。
- 最小消费者聊天界面和人工审批界面。
- 确定性回复质量门禁。
- 固定数据集上的路由、检索、规则和端到端评测。
- Docker Compose 启动、核心自动化测试和演示材料。

### 2.2 移出 MVP

- 知识管理 UI。
- Redis、异步索引任务和完整限流方案。
- 完整 OpenTelemetry 本地观测栈和运营面板。
- 多模型供应商的实际实现；MVP 只实现一个供应商和一个测试替身。
- 独立 LLM Quality Agent。
- 完整物流异常工单流程。
- 用户反馈闭环、Prompt A/B 面板和多租户能力。

这些能力可以保留明确接口或演进说明，但不得为尚未实现的扩展能力预建复杂框架。

## 3. 架构设计

采用模块化单体，外加同仓库内的 Mock 业务 API。核心逻辑角色收缩为三个：

| 角色 | 职责 | 禁止事项 |
| --- | --- | --- |
| Supervisor | 根据当前状态识别意图，选择知识、售后、澄清或升级路径 | 执行业务写操作或决定退款资格 |
| Knowledge Agent | 检索生效政策，形成带引用的回答或证据集合 | 无证据时输出确定结论 |
| Service Agent | 收集售后字段，查询订单，调用资格规则和售后工具 | 覆盖规则结果或绕过资源归属校验 |

人工客服是明确的审批者，不包装成 LLM Agent。

原 Quality Agent 改为确定性 `ResponseValidator`，至少检查：

- 引用标识必须来自实际检索上下文；
- 回复中的订单事实必须来自工具结果；
- 资格结论必须与规则引擎结果一致；
- “已创建”“已完成”等状态声明必须存在成功工具记录；
- 高风险状态不得绕过人工审批。

语言润色可以由现有生成节点完成，不增加第二个评审模型调用。

## 4. 数据流与可靠性

1. API 加载会话、用户上下文和最近检查点。
2. Supervisor 从白名单路径中选择下一步。
3. Knowledge Agent 或 Service Agent 获取证据和业务事实。
4. 确定性规则引擎输出结论、命中规则、缺失字段和风险标记。
5. 高风险流程持久化证据快照并中断，等待人工审批。
6. 恢复时验证审批状态、工作流版本和已有工具执行状态。
7. 写工具使用稳定幂等键；超时后先查询状态，不盲目重试。
8. ResponseValidator 通过后才向用户返回最终结果。

模型、检索或只读工具失败时仅进行有限重试。结构化输出修复最多一次；仍失败则澄清、降级或转人工，工作流不得无限循环。

## 5. 测试与指标

指标在实现前标记为“设计目标”，只有运行固定版本数据集后才可标记为“实测结果”。每个报告必须记录数据集版本、Prompt 版本、模型、代码版本和运行时间。

| 层级 | 最小验证内容 |
| --- | --- |
| 单元测试 | 资格规则边界、Schema、路由条件、引用和状态声明校验 |
| 组件测试 | Retriever、模型测试替身、订单/售后工具、数据库仓储 |
| Graph 测试 | 知识、普通退货、高风险审批、澄清和失败降级路径 |
| 集成测试 | API、数据库、Mock 服务、检查点和幂等执行 |
| E2E | 正常售后主链路及审批期间重启恢复链路 |
| 安全测试 | 越权订单、恶意文档、伪造工具结果和审批绕过 |

核心指标统一定义：

- 任务成功率：固定端到端用例达到期望终态的比例。
- 自动解决率：可自动处理的低风险用例中，无人工介入且成功完成的比例。
- 升级召回率：必须升级的风险用例中，进入人工审批的比例。
- Recall@5：有标注证据的查询中，前五条结果包含相关证据的比例。
- 引用正确率：回答引用确实支持对应声明的比例。

## 6. 三周计划

### 第 1 周：业务与证据基线

- 工程骨架、数据库、迁移和 Mock 数据。
- 订单查询、资源归属校验和统一工具错误。
- 退货资格规则引擎及边界测试。
- 最小知识数据集、向量检索和引用回答。
- 交付一条可通过 API 运行的政策问答或订单查询链路。

### 第 2 周：可恢复工作流

- 模型适配接口、一个真实实现和确定性测试替身。
- Supervisor、Knowledge Agent 和 Service Agent。
- LangGraph 主流程、有限澄清和失败降级。
- 人工审批、中断、检查点恢复和幂等写操作。
- 交付普通退货和高风险审批两条可运行链路。

### 第 3 周：验证与作品集交付

- 最小聊天界面和审批工作台。
- ResponseValidator 和安全回归用例。
- 分层评测集、评测运行器和结果报告。
- E2E、服务重启恢复测试、Docker Compose 和 CI。
- README、架构图、ADR、已知限制和 5–8 分钟演示脚本。

如果进度落后，按以下顺序削减：界面视觉优化、混合检索、完整 Trace 展示、物流扩展示例。不得削减审批恢复、幂等、规则测试和评测报告。

## 7. 完成标准

- 干净环境可按文档启动应用并初始化演示数据。
- 用户可在界面完成正常退货和高风险审批故事。
- 审批期间重启服务后能够恢复，且不重复创建售后申请。
- 所有最终事实和资格结论可追溯到工具、规则或知识证据。
- 固定评测集可重复运行并生成带版本信息的报告。
- 文档明确区分设计目标、实测结果、Mock 能力和未实现能力。
