# T-301 人工审批任务设计

## 范围

T-301 为已由 T-103 判定为高风险或证据冲突的退货建立确定性审批任务，并记录人工的单次终态决定。它不恢复工作流、不创建模拟售后申请、不提供 HTTP/API 或界面；这些分别属于 T-302、T-304、T-401/T-402。

## 可信输入与任务快照

- `ApprovalTaskCreateRequest` 仅接收服务端生成的简短会话摘要。
- `ApprovalTaskContext` 由服务端注入当前用户、已授权订单、目标商品行、资格结论和本次实际使用的政策引用；公开创建输入不能覆盖这些字段。
- 仅 `requires_approval` 且输入绑定、订单/商品行、规则版本和政策引用 ID 完整一致的资格结论可创建任务。
- 任务快照保存会话摘要、订单事实、政策引用、资格与风险原因，供人工无需重新调查即可决定。

## 决定与重复保护

- 任务稳定键由可信用户、订单、商品行、规则版本、适用政策和风险原因派生；同一上下文重复创建返回原任务。
- 审批人仅经 `ApprovalActorContext` 注入。公开决定请求只有决定、备注、调整建议（仅 `adjust`）和期望版本。
- 仅 `pending` 且版本匹配的任务可一次性转为 `approved`、`adjusted` 或 `rejected`；保存处理人、时间、备注和调整建议。
- 已处理、版本冲突、找不到任务、上下文不一致或仓储异常均返回稳定安全结果，绝不替换原决定或触发售后申请写入。

## 边界

批准只是已记录的人工决定，不能表示申请已创建或流程已完成。中断后的恢复、批准后的继续执行、写后确认和最终用户回复不属于 T-301。

## 验证

单元测试覆盖高风险创建、快照完整性、三类决定、幂等创建、终态防重、乐观锁、可信上下文和公开字段拒绝；组件测试通过公开服务路径读取 T-002 的四个 FR-08 固定用例。
