# T-203 标准退货端到端流程设计

## 范围

T-203 以确定性顺序组合已验收的 T-101～T-104 与 T-201～T-202 服务，完成唯一商品行、低风险标准退货的模拟申请闭环。它不实现通用 Agent、LangGraph、审批任务、恢复、持久化会话、HTTP API 或界面。

## 可信边界与流程

- 公开 `StandardReturnRequest` 只接收消息；当前用户身份和已确认收集槽位位于服务端 `StandardReturnContext`。
- 编排先经 T-201 路由与 T-202 收集。信息不完整时立即返回 `COLLECTING_INFORMATION`，不查询资格或创建申请。
- 信息完整后依次调用授权订单查询、政策问答、资格引擎和模拟申请服务。
- 订单必须是已授权且仅有一个商品行；政策回答必须为当前有效、带可信引用的 `answered`；资格必须为低风险 `eligible`；申请必须为 T-104 的 `created` 或 `existing` 成功记录。
- `COMPLETED` 同时携带已授权订单、实际政策引用、资格结果和申请摘要；其余状态不得声称创建申请。

## 安全停止

- 订单不可访问时返回 `ORDER_UNAVAILABLE`，不公开收集快照中的订单号或任何订单事实。
- 政策不足/冲突、商品行不唯一、资格需审批、资格不符合或写入失败均安全停止且不创建审批任务。
- 重复执行委托 T-104 已有稳定幂等键，返回同一已确认申请。

## 验证

组件测试通过公开 `StandardReturnWorkflowService.advance()` 执行固定 `E2E-STANDARD-001`：验证一次完成、政策引用、重复同 ID、缺失信息零写入和越权零泄露。高风险审批与恢复属于 T-301～T-304，不在本任务范围。
