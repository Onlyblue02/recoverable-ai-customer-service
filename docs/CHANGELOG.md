- 完成 T-201 诉求识别与流程引导的执行者实现：新增确定性、无副作用的公开路由服务和类型化可信上下文；覆盖政策、订单、退货、未知澄清及人工升级。

### Known limitations

- T-201 是有限关键词/模式识别，不是通用自然语言理解；不保存会话状态，不包含 T-202 收集/修订、T-203 编排、审批、真实业务操作、Agent、工作流、HTTP API 或界面。

## [0.3.0] - 2026-07-23

阶段二基础业务能力发布。T-101～T-104 均已通过 Reviewer 阶段复审（PASS）。

### Added

- T-101 政策知识与引用回答、T-102 授权订单查询、T-103 确定性退货资格规则、T-104 模拟售后申请与重复保护。
- T-104 仅允许可信身份、授权订单、绑定商品行和低风险资格结果创建模拟申请，并以规范化业务键提供进程内幂等保护。

### Validation

- T-101～T-104 阶段最终记录的专项测试分别为 25、36、39、65 项；对应阶段基线为 34、59、95、135 项；最终全仓 Python 测试记录为 62、98、137、163 项，均通过。
- Ruff、mypy、锁文件检查及前端格式、lint、Vitest、生产构建均通过；保留 1 条 Starlette TestClient 上游弃用警告。
- 当前环境无法识别 Docker CLI，Compose 检查未执行成功，未记为通过。

### Known limitations

- T-104 使用单进程内存模拟仓库，不提供真实退款、持久化、跨进程恢复、审批任务或分布式幂等；真实认证、数据库、Agent、工作流和界面仍属后续范围。

## Unreleased

### Added

- 完成 T-101 政策知识与引用回答的执行者实现：加入基于 T-001 固定 JSON 的类型化政策目录、确定性有效期/范围过滤、冲突检测和安全拒答结果。
- 确定性政策答案只携带本次实际使用的政策引用；引用包含政策 ID、版本、标题、来源、有效期和内容摘录。
- 加入 T-101 单元与组件测试，并直接使用 T-002 的当前、过期、无结果、冲突和无依据政策固定用例验证。
- 补充 T-101 政策专用证据绑定：公开回答前将政策 ID、证据 ID、版本、来源、有效期和内容逐项绑定到本次实际检索并使用的当前政策；无法绑定时返回 `UNGROUNDED_CITATION` 且不公开答案或引用。
- 新增公开 `PolicyAnswerService.answer()` 路径的 6 项伪造引用负向回归测试，覆盖自洽伪造、来源/版本/证据 ID 篡改、引用本次检索外政策和正常引用回归。
- 完成 T-102 订单查询与权限边界的执行者实现：加入固定 JSON 订单仓库、Mock Business 订单 HTTP API、客户服务 HTTP Gateway 与公开订单查询服务。
- 订单查询同时传递当前用户与订单 ID；可信业务仓库负责存在性和归属校验，成功结果使用显式字段白名单，不存在与越权结果不公开订单详情。
- 新增 T-102 单元与公开服务路径组件测试，直接执行 T-002 的授权成功、缺少订单号、订单不存在和订单越权固定用例，并覆盖字段泄露与数据一致性门禁。
- 根据 Reviewer 修复 T-102 身份边界：订单 payload 仅允许订单号，可信用户身份改由独立服务端权限上下文注入，伪造身份和授权字段无法覆盖上下文。
- T-102 对不存在与越权使用相同公开响应以阻止订单枚举，并将仓储、HTTP、解析和下游合同异常统一安全降级为 `ORDER_LOOKUP_UNAVAILABLE`，不公开内部异常文本。
- 新增身份伪造、双身份、批量枚举、RuntimeError 脱敏、HTTP 超时/连接失败、无效 JSON、意外状态及错误码不匹配回归测试。
- 修复 T-102 成功响应串单风险：HTTP Gateway 要求 200 响应中的订单 ID 与本次规范化请求 ID 完全一致；不一致时安全降级且不公开错误订单事实，并新增真实公开服务路径回归测试。
- 完成 T-103 退货资格规则的执行者实现：新增版本化规则配置、确定性 Eligibility Engine、类型化资格/缺失项/风险结果，以及 CNY `5000.00` 包含性高金额阈值。
- T-103 覆盖普通退货、七日包含边界、三十日质量问题核验、八日超期审批、高金额审批、缺失信息、政策冲突、证据绑定和相同输入确定性，并通过 T-002 五个 FR-06 固定用例验证。
- 根据 Reviewer 修复 T-103 唯一政策决策绕过：普通和质量原因只接受各自明确支持的允许决策，`deny` 确定性返回不符合资格，未知或原因错配的决策安全升级且不得自动通过。
- 新增 7 项公开 `EligibilityEngine.evaluate()` 政策 decision 对抗与保留回归，覆盖普通/质量允许、普通/质量拒绝、双向错配、未知决策及重复执行确定性。
- 修复 T-103 高风险审批优先级：超期与高金额风险在唯一政策 decision 前以稳定顺序收集，`deny`、未知或错配 decision 均不能绕过人工审批要求。
- 新增 6 项公开 `EligibilityEngine.evaluate()` 高风险优先级回归，覆盖普通/质量拒绝、高金额、超期、未知/错配 decision、双风险稳定集合及低风险拒绝保留行为。
- 完成 T-104 模拟售后申请与重复保护的执行者实现：新增公开创建服务、冻结输入输出、独立服务端身份上下文及可注入进程内模拟申请仓库。
- 模拟申请仅接受已授权、商品行绑定且低风险 `eligible` 的资格结果；幂等键由可信用户、订单和商品行派生，公开调用方不能提供 `workflow_id` 或随机键绕过重复保护；重复提交返回同一已确认记录。
- 新增 T-104 单元及公开服务路径组件测试，直接复用 T-002 的正常创建、已有申请和写入失败固定用例，并覆盖资格/商品行拦截、写入异常脱敏与响应 Schema。
- 根据 Reviewer 收紧 T-104 可信边界：公开申请 payload 不再接收工作流、幂等键或资格结论；稳定键从可信用户、订单和商品行规范化派生。
- T-103 资格结果新增订单、商品行、产品和规则版本绑定摘要；T-104 通过独立可信资格上下文逐字段绑定，阻止跨订单、跨商品行和伪造低风险结果重放。
- T-104 existing 与 created 路径均严格验证最终 `created` 状态及用户、订单、商品行和幂等键；未知状态、错绑定确认和写后异常统一安全失败且不公开申请编号。
- 修复 T-104 created 确认摘要异常泄露：最终确认和白名单摘要构造均置于统一安全异常边界；空或纯空白申请 ID 等畸形确认安全降级，不传播 Pydantic 校验细节。

## [0.2.0] - 2026-07-20

### Added

- 纳入 T-000 工程基线：Python/FastAPI 与 React/Vite 最小骨架、质量检查、CI 和 Compose 基础配置。
- 完成 T-002 固定验收基线：加入版本化验收清单、38 个语义用例、Draft 2020-12 JSON Schema，以及标准退货和高风险人工审批与恢复两条端到端故事。
- 加入 T-002 Schema 与数据一致性测试，自动校验 P0 正常/异常覆盖、关键安全主题、唯一终态、T-001 引用和端到端副作用合同。
- 完成 T-001 合成业务数据基线：加入版本化用户、商品、订单、模拟售后申请和政策数据，并覆盖正常、边界、失败、越权、无结果与冲突场景。
- 加入 T-001 数据一致性测试，验证版本、文件清单、实体引用、金额、日期、订单归属、政策有效期和场景覆盖。
- 建立阶段版本规划、正式发布门禁和项目唯一版本号规则。
- 建立 `docs/task-reports/T-xxx.md` 任务报告规范。
- 为 T-000、T-001 建立基于现有项目记录的任务报告。

### Changed

- 根据 Reviewer 意见收紧 T-002 Schema，拒绝空语义对象、含糊短文本与纯空白合同；强化普通用例 ID/需求映射，以及有效、过期、无结果和冲突政策与 T-001 事实关系的回归门禁。

### Known limitations

- T-002 是功能实现前的静态验收合同；政策检索、订单查询、资格判断、人工审批和恢复等运行时能力仍由 T-101 及后续任务实现。

- 全仓测试通过，但保留 Starlette TestClient 上游弃用警告和 pytest 缓存目录权限警告。

## 记录规则

- `Unreleased` 只记录已经完成且可核实、但尚未正式发布的变化。
- 正式版本条目必须包含版本号和发布日期，并且只能在对应阶段通过 Reviewer 审查、测试复核和发布检查后创建。
- 计划功能、目标指标、未执行测试和缺失的 Reviewer 结论不得写成实际结果。
- 失败项、已知限制和未完成范围不得从记录中省略或包装成成功。

`v0.2.0` 已通过阶段一 Reviewer 复审。该版本建立工程、合成数据和固定验收合同基线，不包含 T-101 及后续业务功能。
