### Added

- T-604 新增静态、版本化工具注册表和计划校验边界：模型计划只能编译为不可调用的内部步骤；白名单、可信参数来源、用户绑定、状态、预算和重复调用均由确定性代码校验。高风险和人工审批动作不可由模型直调，T-604 不接入或执行任何业务工具。
- T-604 补齐版本化内部 `EvidenceRecord` 合同：生产 authority 不暴露回执创建或登记入口，受控执行器也不接受外部 authority 注入；公开签发仅消费经受控执行路径提供的回执，并使用权威撤销表使原记录及复制版本一并失效；伪造回执、跨绑定、过期、失效、合同或 payload 不一致，以及失败/未知写入结果均不能作为公开证据。
- T-603 新增受限的 `agent-plan-v1` DeepSeek/Fake 计划协议：模型只生成已校验的意图、能力候选和受限参数；沿用一次 JSON 修复，非法或越权输出安全停止。计划只能经 T-602 路由至计划校验、澄清或升级，不注册或调用真实工具，也不改变订单写入、资格裁决或审批边界。
- T-601 完成 Agent MVP 产品、安全与架构设计：固定受控状态机、DeepSeek 有限职责、静态工具白名单、高风险审批—检查点—恢复闭环、可信 EvidenceRecord 生命周期和 T-602～T-607 依赖分解；该设计不表示后续工具、证据回复或生产能力已经实现。
- T-602 Agent 状态机与受控执行器修复：删除公开任意回调执行入口，改用固定无副作用失败替身；通用事件入口拒绝裸审批/恢复事件。
- T-602 新增受限类型化可信审批事件：校验审批、workflow、checkpoint、会话、用户、版本和执行器私有证明，且审批记录与恢复请求保持独立。证明绑定决定、事件类型和单次序号；首次审批决定不可覆盖。该替身不接入真实业务工具、订单/资格裁决、审批决定或写入。
- T-602 新增受限、失败专用检查点分类：缺失、版本不兼容、CAS 冲突和绑定漂移分别记录稳定原因码，且一律安全停止，不能触发恢复或写入。
