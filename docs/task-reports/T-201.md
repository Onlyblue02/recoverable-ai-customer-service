## Reviewer 修复

- 根因：原规则将“能不能退”识别为政策词，并允许订单号或“订单”名词直接触发订单查询，令显式退货混合表达和仅提订单号的政策咨询被订单路由抢占。
- 修复：将显式退货行为置于最高文本优先级；订单查询改为要求明确查询行为或“订单状态”；订单号或“订单”名词不再单独决定订单查询。
- 回归：新增公开 `IntentRoutingService.route()` 路径测试，覆盖显式退货+订单号+资格问句、仅提订单号的政策咨询、含退货语境的明确订单状态查询，以及重复执行确定性。修复后专项测试为 15 passed、全仓 Python 测试为 178 passed；本轮结果仍等待 Reviewer 复审，未标记 PASS。

## Reviewer 第二轮修复

- 根因：首轮“我想/我要……退货”模式允许二者之间任意 12 个字符，将“我想了解/我要查询/我想知道……退货政策或规则”等明确咨询表达误识别为退货申请。
- 修复：先以可审计的咨询行为模式识别政策、规则和条件，再以直接申请/执行表达识别退货；订单查询仍要求明确查询行为。
- 回归：参数化覆盖 Reviewer 指出的三种政策咨询表达，并保留首轮混合退货、明确订单状态查询、纯政策/退货、进行中退货、未知两轮升级和重复确定性。修复后专项测试为 18 passed、全仓 Python 测试为 181 passed。

## Reviewer 结论

- 最终复审：PASS；允许创建 T-201 普通任务提交并进入 T-202，当前不发布新版本 Tag。
