## 实现

1. 新增 `agent-conversation-v1` 与 `agent-modes-v1` 公开合同。默认创建 Fake 会话；DeepSeek 仅在显式选择且后端环境同时配置 Key 与模型名时可选，模式在会话内不可替换。
2. 新增应用级唯一进程内装配图，共享订单、政策、资格、申请、审批、检查点与恢复实例。HTTP 消息入口只接收自然语言和 UUID v4 幂等键，服务端注入固定演示身份与确定性收集结果，然后只调用 `AgentWorkflowService.handle()` / `resume()`。
3. 消费者 API 与审批 API 使用同一依赖图。高风险请求公开为等待审批，人工决定后恢复原 Agent workflow；批准只创建一个申请，重复决定被拒绝。
4. 公开 DTO 只包含模式、用户可见状态、原因码、操作提示、白名单政策引用、申请编号和消息。API Key、prompt、permit、Evidence ID、workflow/checkpoint、原始工具参数、Gate 内部理由与推理链均不公开。
5. 消费者页面新增模式选择、配置可用性、实际模式、模型状态、可信引用与人工审批等待展示。不可用或失败不伪装成 DeepSeek 成功，也不在同一会话静默切换 Fake。
6. 修复真实只读工具在受控状态机中的审计迁移，以及资格评估与高风险编排使用不同参考日期导致的可信证据冲突；两处均复用既有确定性状态机与政策目录，不新增权限或业务规则。
