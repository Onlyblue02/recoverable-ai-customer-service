## 4. 初审阻塞项修复对照

### 4.1 阻塞项 1：高风险审批与恢复工具链不完整

初审问题：原白名单只有审批创建/查询与申请创建，缺少检查点建立和可信恢复工具，可能绕过 T-304 闭环。

本次修复：

- 新增受控 `high_risk.start_or_get`：原子创建或复用审批与绑定检查点；任一失败不得返回等待审批成功。
- 新增受控 `high_risk.resume`：读取服务端 workflow、检查点和可信审批终态，封装 T-302/T-304 恢复闭环。
- 删除 Agent 白名单中的独立 `approval.create_or_get`。
- 明确 `workflow_id` 只能由服务端生成、规范化和保存，模型计划与公开请求不能提供或覆盖。
- 明确高风险资格结果出现后禁止直接调用 `service_case.create`。
- 明确高风险批准后的申请只能由 `high_risk.resume` 内部幂等创建。
- 定义批准、调整、拒绝、重复恢复、审批仍等待、检查点缺失/冲突和写入未知的状态迁移与稳定原因码。

设计位置：

- Agent 状态及外部事件：设计文档第 6 节
- 高风险数据流：设计文档第 7.2 节
- 工具白名单和恢复结果：设计文档第 9.3 节
- 计划校验：设计文档第 9.4 节
- 最终裁决边界：设计文档第 10 节

要求的回归合同已写入 T-605/T-607：

- 伪造审批 ID、缺失检查点、跨会话/用户/workflow 检查点安全失败；
- 批准前不得创建申请；
- 批准后重复恢复返回同一申请；
- 调整、拒绝不得创建申请；
- 高风险计划直接包含 `service_case.create` 时在执行前拒绝。

执行者自检：修复内容已写入，是否关闭由 Reviewer 判定。

### 4.2 阻塞项 2：证据 ID 缺少可信生命周期合同

初审问题：原设计允许计划和草稿引用 evidence ID，但未定义可信签发、绑定、公开字段、失效或 Response Gate 解析协议。

本次修复：

- 新增版本化内部 `EvidenceRecord`。
- 字段覆盖 evidence ID、签发者、工具及合同版本、execution ID、会话/回合/workflow、用户/订单/商品绑定、payload digest、可公开字段、状态、作用域和失效原因。
- 规定只有受控执行器能签发；DeepSeek、用户请求、原始工具响应和回复草稿只能引用，不能创建或修改。
- 规定记录签发后不可变；纠正必须使旧记录失效并签发新记录。
- 默认 turn 作用域；高风险审批快照可使用 workflow 作用域，但必须重新验证完整绑定。
- 工具失败、合同不匹配、绑定漂移和写入状态 unknown 只能形成 non-public 审计记录。
- Response Gate 前必须把当前可信记录解析为服务端类型化 `ResponseEvidenceContext`；ID 本身不构成证据。

设计位置：

- EvidenceRecord 生命周期：设计文档第 9.2 节
- 状态与证据失败：设计文档第 11.3 节
- 安全对抗与证据口径：设计文档第 13.2～13.3 节

要求的回归合同已写入 T-604/T-606/T-607：

- 伪造、跨会话、跨用户、跨订单、过期和失效证据均拒绝；
- 失败工具结果与未知写入状态不能进入可公开证据；
- 伪造证据不能支持“已创建”“已批准”、订单、政策或资格结论；
- 不允许跨会话搜索或以相似 ID 猜测替代证据。

执行者自检：修复内容已写入，是否关闭由 Reviewer 判定。

### 4.3 重要项：状态机外部事件不完整

本次新增事件迁移表，覆盖：

- `user_message`
- `model_result`
- `tool_result`
- `approval_decided`
- `resume_requested`
- `timeout`
- `cancelled`
- `checkpoint_conflict`

每项均定义前置条件、目标状态、业务写操作许可和稳定原因码。

额外约束：

- `approval_decided` 与 `resume_requested` 是两个独立可信事件；
- 检查点缺失、版本/CAS 冲突及跨会话绑定均安全失败。

执行者自检：修复内容已写入，是否满足实施基线由 Reviewer 判定。
