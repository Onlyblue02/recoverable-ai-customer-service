## 目标与范围

为高风险退货创建可复核、可单次决定的人工审批任务。任务包含会话摘要、已授权订单、实际政策引用、资格结论、规则版本和升级原因；人工可批准、调整或拒绝并留下备注。

本任务不恢复流程、不创建售后申请、不实现通用最终回复门禁、HTTP/API、界面、Agent 或 LangGraph。这些能力仍分别属于 T-302～T-304 和阶段五任务。

## 实际修改

- 新增 `customer_service.approvals` 的冻结 Schema、可注入进程内仓储和公开 `ApprovalTaskService`。
- 创建只信任服务端 `ApprovalTaskContext`；资格输入绑定、已授权订单/商品行、规则版本和实际政策引用必须一致，且资格必须明确要求人工审批。
- 任务稳定键从可信用户、订单、商品行、规则版本、政策与风险原因派生。重复创建返回原审批任务。
- 决定请求不携带审批人、订单、风险或证据；审批人由 `ApprovalActorContext` 注入。`pending` 任务只可按乐观版本一次性转为批准、调整或拒绝，并保存处理人、备注、建议和时间。
- 新增单元和组件测试；组件测试直接读取 T-002 的 `AC-FR08-N-001`、`AC-FR08-E-001/002/003`。
- Reviewer 并发修复：仓储 compare-and-set 现在返回本次决定是否实际写入；在读取后被另一请求抢先决定时，公开服务稳定返回 `BLOCKED/APPROVAL_VERSION_CONFLICT`，不把对方的终态作为本次成功结果公开。
