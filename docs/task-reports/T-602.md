## 目标与范围

实现 T-601 定义的显式、有限 Agent 状态机和受控执行器骨架，使状态迁移、计划轮数、执行预算和失败处理均由确定性代码控制。

本任务不接入 DeepSeek，不实现 `AgentPlan` 模型协议、工具注册表、真实工具适配、EvidenceRecord、回复草稿或 Response Gate 集成；这些分别属于 T-603～T-606。它也不修改既有订单、资格、审批、恢复、模拟申请、Response Gate 或 Docker 配置。

## 实际修改

- 新增 `customer_service.agent_runtime`，包含冻结的 `AgentState`、状态/事件/原因码枚举、计划替身、执行预算和审计事件。
- `ControlledAgentExecutor` 以显式状态迁移处理 `user_message`、`model_result`、`tool_result`、`approval_decided`、`resume_requested`、`timeout`、`cancelled` 和 `checkpoint_conflict`。
- 主路径为 `RECEIVED → UNDERSTANDING → PLANNING → VALIDATING_PLAN → EXECUTING → DRAFTING → GATING → COMPLETED`；并实现 `CLARIFYING`、`ESCALATING`、`WAITING_APPROVAL` 与 `FAILED_SAFE` 分支。
- 非法迁移、计划轮次上限、预算超限、重复步骤和执行异常均停止为 `FAILED_SAFE`，并写入稳定原因码和结构化审计事件。
- 确定性计划替身只允许 `read_context` 与 `prepare_draft` 两个无副作用占位步骤；不含工具 ID、参数、身份、资格、审批或写入能力。
- 删除公开任意 `Callable` 入口，执行异常仅由固定、无副作用的失败替身模拟。
- 等待审批时的普通用户消息保持 `WAITING_APPROVAL`；通用事件入口拒绝裸审批/恢复事件。类型化可信事件必须匹配审批、workflow、checkpoint、会话、用户、版本和执行器私有证明；审批决定先记录，独立恢复请求才可进入后续状态。
- 可信证明绑定审批决定、事件类型和单次序号；首次可信审批决定不可变，第二次决定只保留拒绝审计，不改变等待状态、已记录决定或恢复路径。
- 新增受限、失败专用 `CheckpointFailure` 输入；缺失检查点、版本不兼容、CAS 冲突和跨会话/用户/workflow 绑定漂移分别具有稳定原因码，且只能进入 `FAILED_SAFE`。

## 已知限制与风险

- 状态和审计事件仅在进程内对象中存在，不是持久检查点、跨进程恢复或生产审计存储。
- 执行器当前只运行无副作用替身，不调用 DeepSeek、真实工具、资格规则、审批服务、Response Gate 或任何业务写入；可信审批事件库仅为 T-602 的受限进程内测试替身。
- `CHECKPOINT_CONFLICT` 当前验证其安全失败语义；真实检查点绑定、CAS 与恢复端口接入仍属于后续受控工具任务。
- 本任务不能证明 Agent 对自然语言理解、工具权限、证据签发或最终回复的能力。
