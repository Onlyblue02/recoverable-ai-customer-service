# T-104 模拟售后申请与重复保护任务报告

## 实现范围

新增公开 `ServiceCaseService.create()`，以已授权订单和目标商品行创建模拟退货申请。当前用户只由独立 `ServiceCaseAccessContext` 注入；资格结论只由独立 `ServiceCaseEligibilityContext` 注入；公开创建 payload 不能携带工作流、幂等键或资格结论。

仓库为可注入的进程内 `InMemoryServiceCaseRepository`；它可从 T-001 `data/seed/service_cases/service_cases.v1.json` 加载已有 `SC-DEMO-001`，但不会写回固定数据。新增申请仅使用白名单摘要字段：申请 ID、状态、订单 ID 与商品行 ID。

不执行真实退款，不新增 HTTP 写接口、数据库、会话恢复、审批任务、Agent、工作流或界面。

## 决策与安全边界

- 创建前确认商品行属于已授权订单，并要求资格结果同时是 `eligible/eligible` 且 `requires_human_approval=false`。
- 资格不符、质量待核验、超期/高金额审批或商品行不绑定均返回 `blocked`，不调用仓库写入。
- 幂等键固定为规范化的 `user_id + order_id + order_item_id`；公开调用方不能通过随机工作流改变键；同键重复提交返回相同申请并标记 `existing`。
- T-103 `EligibilityResult` 绑定订单、商品行、产品和规则版本；T-104 在写入前逐字段核对，跨订单、跨商品行或伪造资格上下文均不写入。
- 仓库 existing 和 create 确认都必须是 `status=created`，且用户、订单、商品行和键与本次可信请求完全一致，公开结果才可为成功。
- 异常、空确认或非 `created` 确认统一为 `failed_safe/SERVICE_CASE_WRITE_FAILED`，不公开内部异常、不含申请 ID，也不声称“已创建”或“已完成”。
- created 路径的最终确认和 `ServiceCaseSummary` 构造与仓库调用处于同一安全异常边界；任何摘要 Schema 异常（包括空或纯空白申请 ID）均稳定降级，不传播 Pydantic 细节。
- T-001 既有申请按同一可信用户、订单和商品行键导入，允许固定重复场景返回 `SC-DEMO-001`，而不更改 T-001 数据。

## 固定用例

- `AC-FR07-N-001`：公开服务创建唯一模拟申请，状态 `created`。
- `AC-FR07-E-001`：复用 T-001 已有 `SC-DEMO-001`，状态 `existing`，不创建新申请。
- `AC-FR07-E-002`：仓库写入失败时为 `failed_safe`，不携带成功申请或完成声明。

组件测试直接读取 T-002 的结构化用例，而非比较固定自然语言措辞。

## 未覆盖风险

- 模拟申请状态仅保存在单一进程内存；服务重启、跨进程并发、分布式幂等与持久恢复尚未实现。
- 仅模拟申请创建，不执行真实退款或外部业务写入。
- 不创建审批任务，不处理审批后的恢复创建；这些属于后续任务。
- 真实认证、数据库、自然语言抽取、Agent、工作流和界面不在 T-104 范围。
- 当前只有执行者本地验证证据，等待 Reviewer 独立审查。

## Reviewer 问题与修复对应

- 发布记录一致性：更正 `docs/CHANGELOG.md` 中“幂等键绑定工作流”的过时描述，统一为可信用户、订单和商品行派生；定向文本核对确认所有 `workflow_id` 命中均为公开拒绝或安全回归说明，而非实现声明。
- 随机 workflow 绕过：公开 Schema 拒绝 `workflow_id` 和资格字段；稳定键只从可信用户、订单、商品行派生并统一去空格、转大写。相同三元组的连续调用和写后超时重试只保留一条记录。
- 资格跨订单重放：T-103 输出增加确定性输入绑定摘要；T-104 将资格上下文与订单、目标商品行、产品、规则版本逐字段绑定，不匹配为 `blocked/ELIGIBILITY_CONTEXT_MISMATCH`。
- 错误确认公开成功：existing、created 统一要求 `created` 状态及用户、订单、商品行、键严格匹配；pending、unknown、failed、错绑定或空确认返回 `failed_safe/SERVICE_CASE_WRITE_FAILED`，不携带申请摘要。
- 创建确认摘要异常：此前 `_summary(created)` 在 `try/except` 外；现创建确认校验和摘要构造均在统一边界内，空/空白 ID 回归证明公开 `create()` 不抛异常、不返回摘要或成功文本。
