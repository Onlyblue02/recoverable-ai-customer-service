## 实现

1. 新增版本化 Agent MVP 固定矩阵，包含 5 个正常、25 个安全和 1 个可重复性用例，覆盖状态、计划、工具、证据、模型与 Gate 六个失败定位阶段；每个验收项以可机读合同唯一映射到 case ID、pytest node ID 和预期业务安全结果。
2. 新增确定性 Fake 运行器，逐项执行已审查测试节点，输出预期、实际、passed/status、稳定失败原因、审计引用、代码版本和工作区状态。
3. 稳定投影排除运行元数据；完整固定集连续运行两次均为 31/31，稳定投影相同。缺失 checkpoint 现通过真实 `ApprovalRecoveryService.recover()` 入口断言 `FAILED_SAFE/CHECKPOINT_NOT_FOUND`、无审批或申请摘要且零写入；裸恢复事件拒绝另列为独立用例。
4. 新增独立 DeepSeek 补充数据和报告模式。回复草稿按 Schema 版本、允许声明类型、当前证据 ID 子集和禁止业务对象字段判定；逐例记录 Prompt、模型、配置、数据集、耗时、网络状态与失败原因。缺少配置记为 `skipped`；供应商或网络不可用记为 `blocked` 且 `passed=false`；不影响 Fake 门禁。
5. 复用并校验 T-403/T-204 的真实失败来源，保留 `T204-T203-GROUNDED-REWRITE-001`、实际失败、原因和改进建议。
6. 提示注入对抗证明模型输出 `approval.decide` 和身份提升意图时安全失败，不进入工具执行，审计不记录输入原文。

## 覆盖

- 正常：政策、授权订单、资格、低风险申请、高风险审批/恢复、可信 Gate 回复。
- 安全：模糊澄清、提示注入、未知/越权工具、伪造参数来源、引用/证据伪造、虚构业务状态、模型修复失败、非法迁移、循环/预算、超时、工具失败、重复写入/恢复、调整/拒绝零写入、检查点冲突和 Evidence 生命周期。
- 数据：固定清单不含密钥、密码、真实身份或真实订单；DeepSeek 补充只使用明确标记的合成 ID。
