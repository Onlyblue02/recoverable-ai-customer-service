# T-604 工具注册表、计划校验与权限边界

## 范围

本任务只定义静态工具合同并校验 T-603 计划。没有 RAG、订单、资格、审批或申请工具适配器，也没有可执行回调。

## 实现

- 新增版本化 `ToolRegistry`，分类为只读、受控业务请求和模型禁止直调的高风险动作。
- 只读合同：`policy.lookup`、`order.get_authorized`；受控业务请求合同：`return.evaluate`、`service_case.create`；高风险与人工审批动作只用于拒绝模型计划，不能由模型调用。
- 新增可信参数上下文。模型候选参数必须与服务端已有的用户候选、已确认字段或可信工具证据完全匹配；`user_id`、工作流、幂等键等只允许服务端注入，模型结构中出现即被 Schema 拒绝。
- 新增版本化内部 `EvidenceRecord` 合同和受控签发机构。记录绑定签发者、执行、会话、回合、用户、订单/商品、工具/合同版本、作用域、公共字段白名单、有效期、状态、失效原因和 payload 摘要；`EvidenceRecord` 必须经受控执行器持有的机构验证才可信。
- 公开签发入口只消费已由受控执行路径产出的 `TrustedExecutionReceipt`；生产 `InMemoryEvidenceAuthority` 不提供回执创建、登记或测试夹具方法，且受控执行器不接受外部 authority 注入。公开 verifier 仅提供验证与撤销。合法测试回执仅由测试目录的专用 authority 创建；T-605 才接入真实执行回执。失败或未知写入状态没有签发路径；模型或用户伪造的 ID/proof、回执、绑定/合同/payload 漂移、过期或失效记录均不能通过验证。
- 校验器验证白名单、当前状态、参数名称、参数来源、用户绑定、预算和重复调用。成功只生成冻结的 `ValidatedToolStep`，仍停留在 `VALIDATING_PLAN`，不执行工具。
- 缺少所需字段进入 `CLARIFYING`；未知工具、越权、高风险、伪造来源、权限不符、重复调用、预算不足和非法状态都进入 `FAILED_SAFE` 并保留稳定原因码。
