## 实现范围

T-103 新增确定性 Eligibility Engine。输入为 T-102 已授权订单事实、与订单商品行绑定的商品事实、T-001 当前政策证据和结构化退货信息；输出为资格结论、规则版本、适用政策、命中规则、缺失项、风险原因及是否要求人工审批。

不创建审批任务或售后申请，不实现自然语言抽取、Agent、工作流、数据库或界面。

## 规则

- 规则版本：`1.0.0`；固定参考日期：`2026-07-20`。
- 普通退货：`changed_mind`、`resalable`、已签收且处于政策 7 个自然日包含性窗口。
- 质量问题：使用 30 日质量政策；提供 issue code 后返回 `verification_required`，不把问题描述当作已经核验。
- 超期：普通退货第 8 天及以后进入 `requires_approval`。
- 高金额：CNY `5000.00` 及以上进入 `requires_approval`；`4999.99` 不命中。
- 政策冲突、缺少当前依据、商品/订单证据不绑定或日期异常不产生确定性通过结论。
- 唯一政策必须显式执行 `decision`：普通原因只接受 `allow_if_resalable`，质量原因只接受 `allow_after_issue_verification`；明确 `deny` 返回 `ineligible`；未知或原因错配返回 `requires_approval/POLICY_EVIDENCE_INSUFFICIENT`。
- 已知超期和高金额风险先于唯一政策 decision 返回；`deny`、未知或错配 decision 均不能覆盖这些风险。多个已知风险固定按 `OVERDUE_EXCEPTION`、`HIGH_VALUE_ORDER` 排序。
- 缺少原因、普通商品状态、质量 issue code、签收日期或目标商品时返回 `needs_information`。

## 固定用例

- `AC-FR06-N-001`：标准普通退货，`eligible`。
- `AC-FR06-B-001`：签收第七天仍在窗口内，`eligible`。
- `AC-FR06-N-002`：签收第十八天的质量问题使用三十日政策，`verification_required`。
- `AC-FR06-E-001`：普通退货第八天，`requires_approval/OVERDUE_EXCEPTION`。
- `AC-FR06-E-002`：CNY 9999 高金额订单，`requires_approval/HIGH_VALUE_ORDER`。

组件测试通过 `OrderQueryService -> HttpOrderGateway -> Mock Business API` 获取授权订单，再读取 T-001 商品及政策事实并调用公开 Eligibility Engine；用例按语义标签选择，不依赖完整自然语言措辞。

## Reviewer 问题与修复对应

- 根因：唯一政策路径只检查有效期、类别和原因，没有解释 `PolicyDocument.decision`。
- `deny`：公开结果为 `ineligible/ineligible`、`requires_human_approval=false`，`matched_rule_ids=(POLICY_DENIES_RETURN,)`，保留唯一 `applicable_policy_ids` 且无误导风险。
- 原因与允许决策错配：公开结果为 `requires_approval/indeterminate`，规则 ID 为 `POLICY_DECISION_MISMATCH`，风险为 `POLICY_EVIDENCE_INSUFFICIENT`。
- 未知决策：公开结果为同一安全审批组合，规则 ID 为 `UNSUPPORTED_POLICY_DECISION`。
- 支持的普通与质量允许决策保持原有 `eligible` 和 `verification_required` 结果；相同输入重复执行完全一致。
- 第二轮根因：引擎在计算超期和高金额风险前调用 `_apply_policy_decision()`，导致 `deny` 等较低优先级结论提前返回。
- 第二轮修复：在唯一政策和日期确认后，以固定顺序先收集 `OVERDUE_EXCEPTION`、`HIGH_VALUE_ORDER`；非空风险集合统一返回 `requires_approval`，再处理政策 decision。
- 回归覆盖：普通/质量 `deny` 高金额、普通 `deny` 超期、未知或错配 decision 搭配高风险、双风险稳定顺序与重复执行，以及低风险普通 `deny` 保留结果。
