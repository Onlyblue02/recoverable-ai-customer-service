## 实现范围

1. 新增 `agent-response-draft-v1`：模型只能返回文本和按声明类型显式关联的 evidence ID，不接受订单、资格、审批、申请、权限或推理对象。
2. T-605 受控执行成功时在 Evidence authority 内保留与记录对应的类型化只读快照；模型只接收 EvidenceRecord 的最小公开字段。解析器重新验证 proof、有效期、状态、合同、会话、回合、用户、workflow、订单和商品行，并校验快照与记录公开字段一致。
3. `AgentResponseService` 只在 `DRAFTING` 状态调用模型，将引用的可信快照转换为既有 `ResponseDraft` 与 `ResponseEvidenceContext`，再交由 T-303 `ResponseGateService`。只有 `ALLOW` 或无事实的 `SAFE_REWRITE` 可形成公开回复；澄清、升级和证据/模型失败无成功回复。
4. DeepSeek 继续使用零温度、严格 JSON Schema 和最多一次修复；Fake 对相同请求完全确定，并拒绝当前请求外的 evidence ID。
5. 审计仅保留协议/Prompt 版本、输入摘要哈希、evidence ID、模型状态、证据校验结果、Gate 动作和稳定原因码，不记录用户原文、原始模型输出、隐藏推理或密钥。
6. Response Gate 改为结构化事实默认拒绝：无声明自由文本不能 `ALLOW`；有声明时公开事实文本必须等于服务端根据可信类型化对象生成的确定性片段。模型自由文本不能单独形成、否定或改变退款、退货、资格、审批和申请结论；不匹配文本只会安全改写、澄清或升级。

## 安全边界

- 模型不能创建或修改 EvidenceRecord，也不能将草稿中的业务对象提升为可信上下文。
- 未知、伪造、跨回合、跨用户、跨资源、过期、失效或快照漂移证据在模型调用前安全失败。
- 政策引用、订单事实、资格、审批和申请完成分别要求对应受控工具证据；高风险完成同时要求可信批准终态和成功申请证据。
- T-605 的许可、资格裁决、人工审批、幂等写入和恢复边界未改变；T-606 只增加成功结果的内部只读快照交接。
