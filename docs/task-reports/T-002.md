## 目标与范围

基于 T-001 固定合成数据，在任何业务功能实现前建立版本化、机器可校验的验收合同。本任务只定义用例、Schema、清单、数据一致性测试和验收记录；未实现 T-101 或后续政策检索、订单接口、资格规则、Agent、工作流、审批持久化或产品界面。

## 实际修改

- 建立验收集 `racs-fixed-acceptance-suite` 版本 `1.0.0`，固定引用数据集 `racs-core-business-data` 版本 `1.0.0` 和基准日 `2026-07-20`。
- 建立 38 个固定用例，按 routing、retrieval、rules、graph、experience 和 e2e 六个模块组织。
- FR-01～FR-12 每项均至少包含一个正常用例和一个异常或边界用例。
- 覆盖政策问答、订单查询与越权、退货资格、人工审批、中断恢复、无依据回答、虚假完成状态及审批绕过。
- 固定 `E2E-STANDARD-001` 标准退货与 `E2E-HIGH-RISK-001` 高风险人工审批及恢复故事。
- 每个用例记录唯一 ID、需求映射、前置条件、语义用户输入、顺序化期望过程和唯一预期终态；输入提供多个措辞示例，但以语义意图和必要实体作为验收口径。
- 新增 Draft 2020-12 JSON Schema 与自动化一致性测试，并加入 `jsonschema` 开发依赖。
- 根据 Reviewer 阻塞意见收紧 Schema：语义对象必须非空，关键文本必须具有可判断长度且不能只有空白。
- 新增普通用例 ID/需求映射门禁，并按标签逐例验证有效、过期、无结果和冲突政策与 T-001 商品、类别、状态、有效期和完整冲突集合一致。
- 新增含糊合同、错误需求映射和政策 fixture 篡改负例。修复前运行复现 12 个预期失败，修复后专项测试全部通过。
